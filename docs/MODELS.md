# Принести свою модель: обратный путь

[RESIDENCY.md](RESIDENCY.md) закрыл **выход**: профиль руки и веса модели не покидают устройство. Здесь закреплён **вход**: человек должен иметь возможность принести на устройство свою модель распознавания интерфейса через PWA, без участия производителя и без «магазина моделей». Это не лазейка в residency, а её вторая половина: файлы приходят, наружу они не выходят.

Всё проверено **только на симуляции** (настоящее C-ядро моста, шлюз, клиент в Node), см. раздел 0. Людей и платы в проверке не было.

## 0. Честный статус и границы

| Что | Статус |
|---|---|
| Приём модели пакетом `DOPK` (запечатан под одно устройство, подпись отправителя, кнопка для нового отправителя и для каждой модели, хранение в слоте, возврат, снятие) | **реализовано в симуляции, проверено тестами**; основа описана в [UPDATES.md](UPDATES.md) |
| Контракт модели (ABI v1): вход, три выхода, операторы, пределы по размеру, узлам и вычислениям; проверка **статическая** (граф читается, не запускается) | **реализовано и проверено** на малых тестовых моделях и на настоящей экспортированной `UiNet` (в CI, задача `detector`) |
| Свой отправитель у владельца: `dataopen update sender init \| show`, ключи вне устройства | **реализовано**; файл ключей это **симуляция** хранилища секретов (режим 0600), не защищённый элемент |
| Действия `model.clear` (убрать модель слота, профиль остаётся) и `trust.clear` (забыть всех отправителей, нужна кнопка) | **реализовано и проверено в симуляции** |
| Загрузка резидентной модели в детектор из памяти без файла (`ui/resident.py`) | **реализовано и проверено** (ONNX Runtime на CPU) |
| Проверка **не доказывает**, что модель не находит людей, позы или «игроков» | **принципиально**: проверяются метки, формы, операторы, привязка и доверие, но не поведение модели. Это барьеры, а не измерение. Цепочка помощи только вычитает и должна иметь указатель на экране |
| Работа модели в видеопути устройства | **не сделано**: демона модуля (MOD), который держал бы детектор в цикле, нет. «Применена» сейчас значит «сохранена в слоте, проверена, может быть загружена в детектор», а не «работает» |
| NPU RK3588 | **не сделано**: присланная ONNX исполняется на CPU через ONNX Runtime (11 – 16 мс на модели размера `UiNet`, см. [LATENCY.md](LATENCY.md)). Артефакт RKNN от отправителя отдельная часть пакета, её нет |
| Изоляция разбора ONNX в отдельном процессе | **не сделано**: разбор идёт в процессе шлюза; это шаг сборки (песочница) |
| Предел 4 GMAC и 2000 узлов | **допущение, не измерение** (у `UiNet` около 1 GMAC) |
| Качество присланной модели | **не проверяется** устройством; отправитель оценивает её сам (`dataopen ui eval`) |
| Каталог моделей, рейтинг, раздача | **нет и не планируется**: пакет всегда для одного устройства |
| Решение владельца продукта: допускать ли «свою модель» в первой версии | **не принято**; политика здесь предложена, критерий приёмки A-6 в реестре открыт |
| Испытания с людьми | **не проводились** |

## 1. Зачем и для кого

Кому нужно: человеку с редкой программой, нестандартной темой оформления, нестандартным указателем; клинике или технику, который обучил модель под конкретные программы человека; самому владельцу, который умеет обучать (`dataopen ui train`, `export`, `eval`). Им не нужны ни производитель, ни облако.

Кто здесь «владелец»: **отправитель со своим ключом вне устройства**. Устройство само ничего не запечатывает (иначе профиль вышел бы наружу), поэтому «сам владелец» означает, что у него есть собственная личность отправителя (`dataopen update sender init`), и устройство один раз кнопкой согласилось доверять её номеру. Тот же путь у доверенного человека и у клиники.

Чего нет на пути: ключа производителя (он подписывает только системные образы, канал A), магазина, каталога, учётной записи, облака.

## 2. Что можно и что нельзя

Правила, по одному на строку. Таблица создаётся из кода (`dataopen update docs --write`), каждое правило названо причиной отказа.

<!-- fp:model_rules -->
| правило | как проверяется | отказ |
| --- | --- | --- |
| **для этого устройства** | пакет запечатан под Device Public ID; чужой отвергается по заголовку, до данных | `wrong_device` |
| **от известного отправителя** | подпись Ed25519; новый отправитель требует кнопки (`trust:<ID>`) | `bad_signature`, `physical` |
| **каждая модель с кнопкой** | веса принимаются только после нажатия (`model:<ID>`), даже от доверенного | `physical` |
| **только интерфейс** | классы из таксономии `ui-v1`; людей, позы, «игроков», ключевые точки нет | `not_ui_model` |
| **только данные** | белый список операторов; нет внешних файлов, чужих доменов, подграфов | `model_ops`, `model_files` |
| **контракт входа/выходов** | форма, тип и число выходов как у `UiNet` | `model_io` |
| **по размеру и цене** | до 16 МиБ, до 2000 узлов, до 4 GMAC | `too_large`, `model_cost` |
| **потом остаётся на устройстве** | модель лежит под ключом слота; наружу не выходит (карточка без весов) | — |
| **не код** | исполняемого кода, скриптов, внешних данных и каталога моделей нет | — |
<!-- /fp:model_rules -->

Контракт модели (то же, что выдаёт `dataopen update abi`). Это единственное место, откуда читают устройство, инструменты отправителя и этот документ.

<!-- fp:abi -->
| что | правило |
| --- | --- |
| **версия контракта** | `ABI v1`; файл ONNX, один, без внешних данных |
| **таксономия** | `ui-v1`: классы строго из 8 интерфейсных (`button`, `icon`, `text_field`, `menu_item`, `toggle`, `tab`, `window_control`, `cursor`); ключевых точек нет |
| **вход** | один, кадр 640×640: `uint8 NHWC RGB` или `float NCHW 0..255` |
| **выходы** | ровно 3, `p3`, `p4`, `p5`: [N, число_классов + 4, 640/s, 640/s] для s = 8, 16, 32 |
| **число классов** | = число классов в метаданных `ui_layout` = число в карточке пакета (метаданные не могут врать о голове) |
| **операторы** | `Add`, `Cast`, `Concat`, `Constant`, `Conv`, `Identity`, `Mul`, `Relu`, `Resize`, `Transpose`; только стандартный набор (`ai.onnx`), без подграфов |
| **opset** | 7…20 |
| **размер** | до 16 МиБ |
| **узлы** | до 2000 |
| **вычисления** | до 4 GMAC по статическим формам (допущение, не измерение; у UiNet около 1) |
<!-- /fp:abi -->

Явно запрещено: модели людей, поз, «игроков» и любые ключевые точки; произвольный код (любой оператор вне списка, пользовательские домены, вложенные графы, скрипты); внешние файлы данных; модели без привязки к этому устройству; всё, что не умещается в пределы. Отказ всегда называет правило, которое нарушено, и ничего не оставляет на устройстве.

## 3. Как это выглядит для человека

**PWA остаётся «глупым».** Он умеет только выбрать файл (перетащить или выбрать) и отправить его кусками; он не разбирает ONNX, не показывает веса, не читает содержимое пакета. Всё, что он говорит, это слова устройства: принято, отвергнуто с причиной, нужна новая система, применена.

1. **Подготовка (у владельца или клиники, на компьютере).** `dataopen update sender init` один раз; `dataopen update abi` показывает контракт; `dataopen update check-model model.onnx` выполняет на компьютере ту же проверку, что и устройство (с причиной и «что делать»); `dataopen update build-package --to устройство.docard --model model.onnx --model-name имя` запечатывает пакет и печатает, о чём устройство спросит (`trust:<номер>` один раз, `model:<номер>` каждый раз). Инструмент не соберёт то, что устройство отвергло бы.
2. **Загрузка (PWA).** «Загрузить пакет» → выбор файла → «Принято, ждёт применения» со сводкой: от кого (номер), имя, версия, размер, нужна ли кнопка. Или «Отвергнуто: причина» человеческими словами (например «Модель слишком тяжёлая для устройства»), и на устройстве ничего не осталось.
3. **Кнопка на устройстве.** «Применить пакет» в PWA; если отправитель новый, устройство отвечает «нажмите кнопку» (`trust:<номер>`); тот же номер печатал инструмент отправителя, так человек сверяет, кому доверяет. Для весов кнопка нужна каждый раз, от кого бы они ни пришли; первая модель от нового отправителя одним нажатием и делает его доверенным, и принимает веса. Отказ или молчание не тратят нажатие и ничего не меняют; «Отменить пакет» убирает его и не делает никого доверенным.
4. **Применена.** Состояние «Установлена», «Модель принесена отправителем (номер)», имя и версия.
5. **Назад.** «Вернуть прежнюю модель» меняет текущую и прежнюю местами (второе нажатие возвращает обратно). «Убрать модель из слота» удаляет модель и прежнюю копию; профиль, уровни, имя и раскладка слота остаются; кнопка не нужна, потому что это только отнимает возможность. «Очистить слот» стирает слот целиком, вместе с моделью. «Забыть доверенных отправителей» требует кнопки; следующий пакет от кого угодно снова спросит доверие; модели и профили в слотах остаются.

## 4. Что проверяет устройство

Порядок от дешёвого к дорогому; на каждом шаге отказ немедленный, ничего не хранится.

| # | Когда | Проверка | Отказ |
|---|---|---|---|
| 1 | первые куски | заголовок: версия формата, получатель = этот Device Public ID, подпись отправителя, порядковый номер (повтор), требуемая версия системы | `wrong_device`, `bad_signature`, `replay`, `needs_update`, `wrong_channel`, `too_large` |
| 2 | пока идёт передача | порядок и целостность частей, каждая часть связана с номером и признаком «последняя»; пакет не растёт без предела | `sequence`, `damaged`, `truncated` |
| 3 | конец передачи | расшифровка и разбор частей пакета; карточка модели согласуется с байтами (размер, SHA-256) | `bad_part`, `bad_model` |
| 4 | конец передачи | таксономия: классы только из интерфейсных, ключевых точек нет | `not_ui_model` |
| 5 | конец передачи | граф как данные: стандартные операторы из списка, без внешних файлов, чужих доменов, подграфов; opset в пределах | `model_files`, `model_ops` |
| 6 | конец передачи | контракт: вход, три выхода нужной формы, число каналов = классы + 4 | `model_io` |
| 7 | конец передачи | цена: число узлов и умножений-сложений из статических форм | `model_cost` |
| 8 | применение | известен ли отправитель; кнопка для нового (`trust`), для весов всегда (`model`); занят ли шлюз (калибровка, проба системы) | `physical`, `BUSY` |
| 9 | запись | всё пишется атомарно, под ключом слота; перед этим записывается пометка, после перезапуска дело доделывается | — |

Проверка не запускает модель. Карточка с метками и сама модель должны согласоваться: метаданные не могут объявить меньше классов, чем у головы.

## 5. Стыковка

* **Residency.** Модель в слоте под ключом слота; наружу уходит только публичная карточка (без весов и полного хэша). Новые действия добавлены в закрытую поверхность сознательно (`model.clear`, `trust.clear`), состояние `model.from` показывает номер отправителя. Вызовов чтения весов в коде ровно один: `ui/resident.py` (его проверяет тест). Канарейки не находятся ни в одном ответе устройства, ни на диске в открытом виде.
* **Слоты.** Одна модель на слот; очистка слота и сбросы стирают модель; смена слота меняет и детектор.
* **DOPK / DOBS.** Модель только в `DOPK` (под один Device Public ID, потоково, голова судится первой); малые файлы `DOBS` моделей не несут.
* **Две линии обновлений.** Канал A (система) не трогает модель; пакет с `min_fw` выше работающей версии отвергается с `needs_update`, а после отката системы ниже `min_fw` модель остаётся и состояние `needs_system`; во время пробы новой системы пакеты ждут (`BUSY`), во время калибровки тоже.
* **Сбросы.** Стирание личных данных и заводской сброс убирают модели и доверенных отправителей; сброс отправителей без стирания это `trust.clear`.

## 6. Что сознательно не сделано

* Проверка поведения: модель, прошедшая все барьеры, всё же может находить не то, что обещает её карточка. Защита это совокупность барьеров (метки, форма, привязка, доверие, кнопка на каждую модель) и указатель на экране, а не доказательство.
* Демон модуля и подключение детектора к видеопути; пока детектор из слота собирается, но в цикле не работает.
* RKNN/NPU и измерение на плате; все цифры времени получены на CPU и в симуляции.
* Изоляция разбора ONNX в отдельный процесс.
* Подпись и защищённое хранилище ключей отправителя (файл ключей это симуляция).
* Повтор после `trust.clear`: вместе с отправителем забывается и последний номер его пакетов, поэтому старый перехваченный пакет можно предъявить снова; он запечатан под это устройство, но для его применения теперь нужны две кнопки (доверие и веса). Это принято как компромисс простоты, оценка риска R-13 в реестре.
* Автоматическая оценка качества присланных моделей и каталог.
* Отзыв модели на устройстве другого человека: у устройства нет связи с производителем, отзывать нечем и некому.

## 7. Команды и файлы

```
dataopen update sender init [--dir D] [--name N]      # своя личность отправителя
dataopen update sender show                           # номер, который покажет устройство
dataopen update abi [--json]                          # контракт модели
dataopen update check-model model.onnx                # проверка, как на устройстве, с причиной
dataopen update build-package --to dev.docard --slot 1 --model model.onnx --model-name имя
dataopen update docs --write | --check                # таблицы в UPDATES.md и MODELS.md
```

Файлы: `src/dataopen/updates/models.py` (контракт и проверка), `sender.py` (личность отправителя), `manager.py` (хранилище модели, `clear`), `ui/resident.py` (детектор из памяти), `tests/test_models_custom.py` (правила, поток, откат, residency, загрузчик, инструменты), `tests/test_models_torch.py` (настоящая `UiNet` целиком, в CI), `pwa/tests/models.test.mjs` (клиент «глупый»).
