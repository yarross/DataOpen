# Резидентность модели и профиля: они живут только на устройстве

Правило, которое пришло от security-инженера ассистивных и медицинских устройств: **моторный профиль человека и веса его модели после применения живут только на устройстве.** Профиль руки и веса, обученные под эту руку, по сути персональные данные. Ни пользователь, ни поддержка, ни приложение на телефоне не должны иметь способа «скачать их обратно».

Это не настройка и не то, что «не показывает интерфейс». Правило держится на трёх вещах, которые проверяются:

1. **Нет кода, который их отдаёт.** В протоколе нет «экспорта», «прочитать профиль», «прочитать модель». В манифесте нет файловой операции, которая возвращает данные устройства (только открытая карточка). В шлюзе нет функции, которая запечатывает профиль для кого бы то ни было, в том числе для самого себя.
2. **Поверхность закрыта.** Что телефон может спросить, задать, запустить; какие сообщения устройство может отправить; какие операции бывают у файлового контрола: всё это списки в `src/dataopen/ctl/residency.py`, и тест их закрепляет. Добавить пункт значит принять решение и записать его, а не получить побочный эффект.
3. **Всё, что устройство говорит, проходит одну дверь.** Каждый ответ сверяется со схемой по принципу «запрещено всё, чего нет в списке»: лишний ключ, длинная строка, значение вне словаря или слишком большой ответ не отправляются, а считаются (`egress_blocked`).

## 0. Честный статус и границы

| Что | Статус |
|---|---|
| Закрытая поверхность протокола, схемы ответов, единая дверь исхода, отказ `RESIDENT`, удалённый экспорт, отказ для файла «от самого устройства» | **Реализовано и проверено на хосте и в симуляции** (`tests/test_residency.py`, `pwa/tests/residency.test.mjs`, канарейки в сквозной приёмке) |
| Данные на диске только шифртекстом под ключом слота; сброс заменяет ключ, и сохранённая копия шифртекста бесполезна | **Реализовано в симуляции и проверено** |
| Утилита поддержки и система восстановления только удаляют, не читают | **Проверено на модели утилиты** (чтение `slots/` и `pkg/` запрещено на время работы `full_return`) |
| Защита от **root на модуле**, от физического извлечения ключей из железа | **Не сделана.** Ключи сейчас лежат в файле (`FileKeyStore`); нужен secure element, расшифровка внутри доверенной среды и закрытая отладка |
| Исполнение модели в песочнице (читать веса может только процесс, который её запускает) | **Не сделано**: модель пока не исполняется, вызовов `ModelStore.weights()` в коде нет вовсе |
| Независимая проверка, пентест | **Не проводилась** |

**Цена правила (принято сознательно).** Профиль нельзя выгрузить никуда: ни «копией для себя», ни на запасное устройство. Поэтому **нет резервной копии профиля и нет переноса профиля на новое устройство**. Замена устройства значит повторную калибровку, потеря раздела данных или secure element значит потерю профиля. В устройство профиль и модель по-прежнему можно **загрузить**: пакет `DOPK` или малый файл `DOBS`, сделанный отправителем со своими данными (клиника, техник), запечатанный для этого устройства. Поток только внутрь.

## 1. Классы и правила

<!-- fp:classes -->
| класс | что значит |
| --- | --- |
| `secret` | секрет: живёт только на устройстве, наружу не выходит ни в каком виде |
| `personal` | личное: видно владельцу в приложении, файлом наружу не выходит |
| `derived` | грубая производная: несколько значений из фиксированного списка |
| `metadata` | метаданные: серийник, версии, состояния |
| `public` | открытое: можно передавать любому |
<!-- /fp:classes -->

Для каждого объекта: что видит телефон, можно ли его выгрузить, где он живёт и что с ним делает каждый из четырёх уровней сброса (L1 очистить слот, L2 стереть все профили, L3 заводской сброс, L4 полный возврат сервисом; подробности: [PROVISIONING.md](PROVISIONING.md) §5).

Строки про профиль, модель и ожидающий пакет **проверяются тестом на настоящем шлюзе** для L1–L3 (`test_the_reset_levels_erase_exactly_what_the_rules_table_says_about_the_secrets`); L4 проверяется на каталоге устройства (`full_return` удаляет `slots/` и `pkg/`).

## 2. Закрытая поверхность

<!-- fp:surface -->
| что | полный список |
| --- | --- |
| `GET` (что устройство может сказать телефону) | `manifest`, `state`, `identity`, `slots`, `firmware`, `packages` |
| `SET` (что телефон может задать) | `assist.on`, `assist.strength`, `tremor.level`, `calib.running`, `slot.name`, `slot.active` |
| `ACT` (что телефон может запустить) | `profile.restore`, `pairing.forget`, `erase.profile`, `factory.reset`, `slot.clear`, `fw.apply`, `fw.rollback`, `pkg.apply`, `pkg.discard`, `pkg.revert` |
| файл: в устройство | `bundle_put`, `fw_put`, `pkg_put` |
| файл: из устройства | `card_get` (открытая карточка) |
| сообщения от устройства | `HELLO_R`, `DATA`, `ACK`, `ERR`, `EVENT`, `PONG` |
| запрос секрета (`what` = …) | `bundle`, `profile`, `profile_prev`, `model`, `weights`, `export`, `backup`, `slot_data`, `params`, `keys`, `dump`, `copy`, `download` → ошибка `RESIDENT` (19) |
| размеры | ответ ≤ 4096 байт (кроме раскладки), событие ≤ 1024, `detail` ошибки ≤ 96 символов, строка ≤ 64 |
<!-- /fp:surface -->

Что значит «запрос секрета»: если телефон (или кто угодно по CtlLink) спросит `GET` с одним из этих имён, ответ `ERR RESIDENT`, а не `BAD_KEY`. Это нужно, чтобы отказ был виден как намеренный, а не как «функцию забыли». Остальные неизвестные имена получают `BAD_KEY`.

Единственное, что устройство отдаёт в файл, это **открытая карточка** (`card_get`): ключи и номер. По ней ничего нельзя прочитать, можно только подготовить файл для этого устройства.

## 3. Что может и чего не может приложение на телефоне

| Приложение может | Приложение не может |
|---|---|
| загрузить пакет `DOPK` (профиль, уровни, раскладка, имя, веса) и файл `DOBS` на устройство | прочитать профиль или веса, получить копию, сохранить их в файл (метода нет в клиенте, запрос не покидает страницу, устройство ответило бы `RESIDENT`) |
| увидеть статус: есть ли модель, `needs_system`, имя и версия, короткий `id`, размер; сколько собрано профиля (0..100) | увидеть полный хэш весов, содержимое профиля, параметры, посчитанные из него |
| откатить прежнюю модель (`pkg.revert`), прежний профиль (`profile.restore`) | скачать прежнюю модель или прежний профиль |
| очистить слот, стереть все профили, заводской сброс (кнопка на устройстве) | вернуть стёртое |
| сохранить **открытую карточку** устройства | сохранить что-либо ещё из устройства |
| менять уровни, имя слота, слот, включать и выключать помощь | задать устройству «отдай файл» через раскладку: операции файлового контрола ограничены списком, чужой манифест с другой операцией отвергается |

Браузерная страница хранит только язык, оформление, защиту от повторных нажатий и кэш **раскладки** по её хэшу. Профиля и весов у неё нет ни на каком этапе.

## 4. Стыковка со слотами, пакетами, файлами и сбросами

* **Слоты** ([SLOTS.md](SLOTS.md)). Профиль, модель и прежнее поколение лежат в каталоге слота под ключом слота (`HKDF(ключ диска, номер, эпоха)`). Очистка слота увеличивает эпоху: сохранённый шифртекст этого слота больше не читается. Файла «всех слотов» наружу нет; есть только файл **внутрь** с секцией `slot` (его делает отправитель).
* **Пакет DOPK** ([UPDATES.md](UPDATES.md)). Канал B несёт веса и профиль **в устройство**. Файл, запечатанный самим этим устройством (отправитель равен получателю), отвергается с причиной `own_file`: устройство файлов не делает, такой файл возможен только от украденных ключей. В читаемых ответах у модели вместо полного SHA-256 весов короткий `id` (первые 8 байт); полный хэш остаётся внутри для проверки установки.
* **Файл DOBS** ([SECURITY.md](SECURITY.md)). Формат остался (и «копия для себя» в формате есть), но устройство его **не производит**; принимает от отправителя, при этом файл с отправителем «это же устройство» отвергается с `own_file`.
* **Сбросы L1–L4.** Все четыре только удаляют (замена ключей и файлов). Результат `full_return` и отчёт станции содержат только метаданные: серийник, версии образов, порог анти-отката, стадию жизненного цикла. Модель восстановления (`dataopen recover simulate`) называет для события только «профили сохраняются / теряются (калибровка заново)», а не копию.
* **Восстановление.** Система восстановления не трогает раздел данных и не читает его; утилита поддержки и `full_return` проверены при запрещённом чтении `slots/` и `pkg/`.

## 6. Чего нет

* **Защиты от root на модуле.** Ключи в файле; кто читает файл ключей, расшифрует каталог. Нужны: secure element (ключи не выходят из чипа), доверенная среда для расшифровки, закрытая отладка. Критерий готовности S-7, шаг 5 порядка работ ([V1.md](V1.md)).
* **Защиты от извлечения ключей физически**, от снятия флеш-памяти вместе с ключами. Для этого нужно железо.
* **Песочницы для модели.** Модель ещё не исполняется. Когда её запустит процесс детектора, читать веса сможет только он; список мест вызова `ModelStore.weights()` закреплён тестом (сегодня пустой).
* **Независимой проверки.** Список закрыт и проверяется своими тестами; внешнего аудита не было.
* **Резервной копии профиля.** Сознательно (см. §0).
